# b²c v2: Canvas as an OS for schoolwork, built from primitives

Dev lead, 2026-10-20. North star (INTENT.md, 2026-10-20): everyone's Canvas
can look like their own customised ("riced") desktop, while staying fast and
light. v2 builds the rice out of a few **primitives** rather than more
toggles. Design owns the Studio UX that sits on top of them.

## The primitives

### 1. Tokens and the theme engine

- **A theme is one versioned, shareable file**: palette (light and/or dark
  roles), font, corner, density, card style, layout and views. It is
  applied **before first paint** through the existing mirror. Every theme
  value compiles to `--b2c-*` vars and `data-b2c-*` attrs, so no new runtime
  mechanism is needed.
- **One palette engine for light and dark.** Dark mode's machinery
  (the literal map of Canvas's compiled CSS, the generated gated overrides,
  the InstUI layer, the authored-colour remap) generalises to *any* palette.
  A custom light theme, a sepia one or a high-contrast one all use the same
  engine. Dark is just the built-in dark preset.
- **Canvas-level tokens, not just b²c's.** Corner, density and font apply to
  Canvas's own surfaces (cards, buttons, nav, tables), the way palette roles
  already do. That's what makes it "riced" rather than "skinned".
- **Sharing needs no server:** export to a `.b2c-theme.json` file, or a
  compact share code (base64url of the JSON) to paste. Import validates
  against the format version, previews live, then applies with Undo.
- The format is agreed with Design (proposal below).

### 2. Regions and layouts

Named regions b²c owns: the dashboard **grid** (cards), the **side panel**
(sections, order, side), and a **dock** for pins and search. A layout
(theme-carried) says what goes where: panel left, right or hidden; section
order; card grid columns and width. Core provides the region registry. The
side panel already exists in core and generalises to N regions.

### 3. Views

A feature's data can be shown through several **views**:
`defineView({ feature, id, render(host, model) })`. The to-do list gets list
(today), **wheel** (bc's, which she misses), week strip and by-course board,
all over the same model, with the same actions and planner sync. The current
view is a theme and layout choice. Views should feel rewarding: a satisfying
tick, progress that reads at a glance.

### 4. Pins (week-aware bookmarks)

A pin is `{ label, icon?, target }`, where `target` is either a URL or a
**query** resolved live against Canvas data. Examples:
`{kind:'module', course, which:'this-week'}`,
`{kind:'next-due', course?}`,
`{kind:'latest-file', course, match:'lecture'}`,
`{kind:'page', course, match:'syllabus'}`. Resolvers use the shared data layer
and a **week model** (term start, module names and dates, assignment clusters;
Research is studying how schools name weeks). Pins live in the dock and in
⌘K. "Pin this page" works from anywhere.

### 5. Search (⌘K)

A local index of courses, modules and items, assignments, pages, files,
discussions and announcements, built only from **read-safe list endpoints**
(never an item view, which marks things read). It's stored per user on the
Canvas origin (IndexedDB), refreshed incrementally, and nothing leaves the
device. The ⌘K palette searches the index, pins and **commands** ("dark mode
off", "open GPA settings", "pin this page"), which is what makes it feel like
an OS. Results are instant (<16 ms per keystroke on the heavy mock).

### 6. Speed and weight are hard constraints

- **Budgets** are in `dev/budgets.json` and enforced by ship. They cover bytes
  per artifact (boot, core, each feature chunk, content.css), main-thread time
  per feature `start()` on the heavy mock at 4× CPU, requests per page kind, and
  zero b²c work on pages a feature doesn't apply to. A ship prints a budget
  report and fails on any regression.
- **Code-splitting.** `main.js` (194 KB today) becomes a small core plus
  per-feature chunks loaded only on pages where the feature runs. Each
  feature splits into a tiny synchronous **definition** (settings, pages,
  mirror) and a lazily imported **runtime** (`start`). Pre-paint is
  unaffected because mirrors stay synchronous in core.
- **Hover-intent prefetch** (speculation rules) on read-safe routes only
  (dashboard, course home, modules list, assignments list, calendar), so
  Canvas navigation feels instant. It's measured, and kept only if it earns its
  keep.
- **Drift watch:** the probe runs quietly on each page. A missing anchor
  surfaces in the popup in plain words and in Diagnostics.

## Theme format: Dev's proposal to Design (v1)

```jsonc
{
  "$b2c": "theme", "v": 1,
  "name": "Night Garden", "author": "optional",
  "mode": "dark",                         // light | dark | system (pair)
  "palette": {                            // roles; one set per mode used
    "light": { "bg": "#…", "surface": "#…", "surfaceRaised": "#…", "border": "#…",
               "text": "#…", "textSecondary": "#…", "textTertiary": "#…",
               "link": "school" | "#…", "nav": "school" | "#…", "navText": "#…",
               "accent": "#…" },
    "dark":  { … }
  },
  "type":    { "family": "Inter" | "System" | …, "scale": 1.0 },
  "shape":   { "corner": 2 },             // px; feeds --b2c-corner (b²c + Canvas)
  "density": "compact" | "cozy" | "roomy",
  "cards":   { "style": "flat" | "gradient" | "image", "height": "normal" | "condensed",
               "overlay": true, "width": 262, "gap": 36, "colors": { recipe } },
  "layout":  { "width": "standard" | "wide" | "full", "panel": "right" | "left" | "hidden",
               "sections": ["todo", "notes", "gpa"] },
  "views":   { "todo": "list" | "wheel" | "week" | "board" },
  "css":     "optional user CSS (scoped, as custom-css)"
}
```

- Every field is optional, and a theme overrides only what it names.
- Applying a theme writes the corresponding setting keys (one transaction,
  with Undo). Exporting reads them back. So the Studio, the popup and the
  settings page always agree.
- Unknown fields are kept and reported. `v` bumps only for breaking changes.

## Order of work

1. **Core, Dev lead (now):** budgets, code-splitting, the speed report in
   ship. This sets the floor for everything else.
2. **Lanes in parallel:**
   - **search** (⌘K index, palette and commands);
   - **pins** (resolvers, week model, dock; waits on Research's week study
     for the naming heuristics);
   - **palette engine** (dark → any palette, plus Canvas-level corner, density
     and font tokens; the dark lane);
   - **theme format and engine** (after Design agrees the format);
   - **to-do views** (after Design's view specs; the todo lane).
3. **Studio:** Design's direct-manipulation UX on these primitives, built by the
   ui lane once its spec lands.
